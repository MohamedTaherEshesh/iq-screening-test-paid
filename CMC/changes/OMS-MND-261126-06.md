# OMS-MND-261126-06: Exam price as a server variable Price_<ExamName>, with history

Status: BUILT on DEV, AI tests passed. Waiting for: database change applied, owner deploys exam-payment and admin-analytics, test.

## Request (owner, 2026-11-26)
Each exam's price comes from a server-side global variable "Price_<ExamName>", changeable at any time from the admin Assessment page. The next call uses the new price. The old price keeps its history: its valid-to date equals the new price's valid-from date.

## Change
- New table `exam_price_history`: Price_University_IQ_Preparation and Price_University_Cognitive_Skills, both starting at USD 10 (today's price). One open row per exam = current price.
- `set_exam_price` closes the open row and opens the new one at the same moment (valid_to old = valid_from new).
- exam-payment reads the exam's current price on the server, signs it into the quote together with the price row id, and checks it again at checkout. If the price changed in between, the page refreshes the quote once and shows the new amount. Each payment stores the price row it used (exam_payments.price_id).
- The pay button shows the real price from the server instead of the fixed "10 USD".
- Admin page, Assessment: "Exam prices" card shows each variable, current price, valid from, a box to set a new price (with confirmation), and the full history.
- Backward compatible: until the new exam-payment is deployed, the old fixed USD 10 checkout keeps working.

## Value added
Prices can change in seconds without a developer; every payment can be traced to the price that applied.

## Impacted areas
Supabase: exam_price_history, current_exam_price, set_exam_price, assert_exam_price_quote, reserve_exam_payment (extended), exam_payments.price_id. Edge functions exam-payment, admin-analytics. Web: university-client.js. omsaze-corporate admin.js.

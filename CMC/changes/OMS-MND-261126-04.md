# OMS-MND-261126-04: Certificate verification by QR code

Status: BUILT on DEV (branch feature/results-verify-price), AI tests passed. Waiting for: database change applied, owner deploys exam-payment and exam-payment-webhook, owner human test.

## Request (owner, 2026-11-26)
Any company, university or employer that scans the QR on a certificate reaches a verification page showing name, score, date and validity.

## Change
- Database: each result record (see OMS-MND-261126-05) gets a random code `MP-XXXX-XXXX-XXXX` (60 bits, cannot be guessed). The certificate becomes **valid** when the exam is paid, **revoked** if the payment is refunded, and is valid for **24 months** from issue.
- Public function `verify_certificate(code)` returns only: name, exam, score, exam date, issue date, valid-until, status. Never email, birth date, country, answers or payment data.
- Certificate PDF: QR code (top right; top left on Arabic certificates) + the code printed under it + "Scan to verify". The certificate date is now the exam date, so every copy shows the same date.
- New page `verify.html` (English/Arabic, phone friendly). Manual code entry also works.
- QR link: `https://staging.omsaze.com/verify.html?c=<code>`. For production set the secret `OMSAZE_CERT_VERIFY_URL` (no code change).

## Value added
Third parties can check a certificate in seconds; fake or edited certificates are detected.

## Impacted areas
Supabase: table exam_results (new columns), functions new_certificate_code, verify_certificate, triggers on exam_payments/exam_results. Edge functions exam-payment and exam-payment-webhook (_shared/certificate.ts, _shared/certificate-verify.ts). Web: verify.html.
